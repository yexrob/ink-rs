## Where this phase sits

M0 renders an element tree once: `host::build` turns an `Element` into a `HostTree`, then layout and paint run. M1 adds components with hooks, in three phases:
- **Phase 1 (this one):** the runtime core, with `render_to_string` moved onto it.
- **Phase 2:** the stepping core (`render_if_due`) and `testing::render`, which keep a tree mounted across frames, re-render dirty components and reconcile a new root element against the mounted tree.
- **Phase 3:** `use_node_ref` and `measure_element`.

Design this phase so phase 2 can be added without reshaping it, but add no API that only phase 2 would call.

## 1. Public API

- **`component(f, props) -> Element`**
  - `f: Fn(&mut Scope, &P) -> Element + 'static`, and `P: PartialEq + 'static`.
  - Component identity is the `TypeId` of `F`.
  - Require `F` to be zero-sized, checked with an inline `const` assertion and a clear message. Function items and non-capturing closures pass. Function pointers fail, because they all share one type. Capturing closures fail, because their captures would bypass the props comparison.
- **Keys**
  - `Element::key(self, key) -> Element`, plus `.key(..)` on `View`, `Text`, `Static` and `Transform`, returning `Element`.
  - A key is a string or an integer. As in React, keys apply among siblings.
- **Hooks on `Scope`**
  - `use_state(init: impl FnOnce() -> T) -> State<T>`
  - `use_memo(deps, f: impl FnOnce() -> T) -> T`, where `T: Clone`.
  - `use_effect(deps, f)` and `use_layout_effect(deps, f)`, where `f: impl FnOnce() -> C + 'static`:
    - The effect runs on mount, and again when the deps change.
    - The value it returns is its cleanup. It is dropped before the effect runs again, and on unmount.
    - `()` as the deps means "run once".
  - Deps are `D: PartialEq + 'static`.
- **`State<T>`**
  - `Copy`, with `get()` (`T: Clone`), `set(v)` and `update(|v| ..)`.
  - `set` requires `T: PartialEq`. An equal value marks nothing dirty. `update` always marks the owner dirty.
  - It is a generational handle (runtime id, slot, generation) resolved through a thread-local registry. Several runtimes can live on one thread; phase 2 tests run two at once.
  - A write on the UI thread from anywhere marks the owning component dirty. That includes effects, cleanups, other runtimes' code and plain test code, but not render.
  - After the component unmounts, a write is ignored and a read panics.
- **Debug builds**
  - A state write during render panics.
  - Hooks called in a different order (the kind recorded per position) panic, and the message names the component's type.
- **`render_to_string`** keeps its signature.

Export the new items from `src/lib.rs`, and update the crate docs, which still describe M0.

## 2. The runtime

### Structure and host tree

- Create a module `src/runtime/`, split as you see fit.
- It owns the instance tree and the `HostTree`. Reconciliation applies host mutations directly: create, `set_props`, insert, remove.
- `host::build` goes away. A first mount must produce the same host tree `build` produced; the existing 616 tests check this, including the root node's style.

### Reconciliation (as React)

- Keyed children match by key; unkeyed children match by position.
- A different element kind, component type or key unmounts the old instance and mounts a new one.
- A moved keyed child moves its host node (`insert_child` with `before`).
- Free removed host subtrees for reuse. M0 left `remove_child` detaching without freeing for this phase. A reused slot must not keep the old node's cache, layout or links.

### Components

- A component re-renders when it is dirty or its props changed; otherwise its subtree is skipped.
- Dirty components render parents first, in one pass. A dirty child that re-renders during its parent's pass does not render a second time.

### Views

- A `View` whose `Style` is unchanged is not touched: `set_props` clears layout caches up to the root.
- `set_props` replaces the whole style and `map_style` maps it from scratch, so a removed builder call renders as if it was never set. Keep that property; phase 2 ports the style-removal tests on it.

### Text

- As in M0, a top-level `Text` or `Transform` is one host leaf holding an inline tree (`TextNode`). Nested `Text`, `Transform`, strings and components under it form that tree.
- Components inside text are instances with hooks like any other.
- The enclosing leaf's inline tree is rebuilt when anything under it changes. That includes a nested component that re-renders on its own state.
- An unchanged inline tree leaves the host node alone.
- A `Transform` function cannot be compared. A leaf whose inline tree holds one counts as changed every time its owner renders; Ink marks such nodes dirty on every update (`src/dom.ts:230-240`).
- A `View` or `Static` inside text panics with the existing message.
- A `Text` with no children creates no host node, as `build` does.

### Background

- A View's `background_color` reaches descendant Text as it does in `build`, through an internal context (Ink's `BackgroundContext`).
- When it changes, update the affected Text host nodes without re-running user components whose props are equal. In Ink only the Text that reads the context re-renders.

### Static

- `Static` stays a host node (`is_static`). Each render of its owner renders every item through the closure.
- The items are its children, matched by key or position.
- Writing only new items belongs to the M2 output layer. Do not track items here.

### Effects (React's order)

- Within a commit, cleanups of effects that re-run, and of unmounted instances, run before any new setup.
- Setups run children before parents.
- In an unmounted subtree, cleanups run parents before children.
- Effects and cleanups run while no borrow of runtime state is held, so they can read and write any `State`, including one from another runtime.

## 3. One frame

Follow design.md 一帧 step 2:

1. Render dirty components and apply host mutations.
2. Run `layout::compute`.
3. Run the `use_layout_effect` setups. If they dirtied anything, go back to step 1. Cap this at 50 rounds, then panic, like React's maximum update depth.
4. Paint.
5. The caller writes the frame.
6. Run `use_effect`.

Put this sequence in one place: `render_to_string` uses it now, and phase 2's stepping core will reuse it.

`render_to_string` mounts, runs one frame, serializes it, runs `use_effect`, then unmounts, which runs the cleanups. State written by `use_effect` does not reach the output.

Teardown must also happen when a panic unwinds out of the frame. In RS4, a Transform function panics during paint:
- The layout effect's setup ran once, and its cleanup ran once.
- The panic reaches the caller.
- The next `render_to_string` call on the same thread works.

Make unmount the runtime's `Drop`, not a `catch_unwind`.
