## 1. Commit and present

Split `Runtime::frame` into two steps, matching design.md 一帧:

- **Commit**: render dirty components → host mutations → `layout::compute` → layout effects; if they dirtied anything, repeat (the 50-round cap stays).
- **Present**: paint → hand the frame to the caller → passive effects.

`render_if_due(now: Instant, ...) -> Option<Instant>`:
- When something is dirty, it commits, then presents. In M1 every commit is presented at once (no throttle).
- It returns `Some(now)` when work is pending afterwards (a passive effect dirtied state), and `None` when idle.
- When nothing is dirty, it renders nothing and returns `None`.
- `now` has no use until M2's throttle. Keep it in the signature, as design.md specifies.

`render_to_string` keeps its behaviour and goes through the same steps.

## 2. Dirty tracking

Phase 1 finds dirty instances with `has_dirty`, which scans a whole subtree at each level of `reconcile` and again after layout effects. Replace it:

- Checking whether a runtime has any pending work is O(1). The idle path relies on it.
- Reconciliation visits only the paths from the root to dirty instances and the subtrees that re-render, like React's `markUpdateLaneFromFiberToRoot` and `childLanes`. A hint: a state write sets its owner's flag and walks parent links upward, setting a "descendant dirty" flag until it meets one already set.
- A write after unmount stays ignored. A write from another runtime's effect marks the owning runtime, not the current one.

## 3. Effect order (React's)

Phase 1 runs the cleanups of re-running passive effects before layout. Match React:

1. Mutation phase:
   - the cleanups of unmounted instances' layout effects, parents before children;
   - then the cleanups of re-running layout effects.
2. Layout phase: layout-effect setups, children before parents.
3. After present:
   - the cleanups of unmounted instances' passive effects, parents before children;
   - then the cleanups of re-running passive effects;
   - then passive setups, children before parents.

An unmounted instance's state slots are released after its passive cleanups, so a cleanup can still read the instance's own state. Effects and cleanups run while no runtime borrow is held, as in phase 1.

## 4. `testing::render`

A public module `testing`, the counterpart of ink-testing-library's debug mode (design.md 测试, layer 2):

- `testing::render(element) -> TestInstance`: 100 columns, `ColorLevel::Basic`, like `tests/common::render`.
- `testing::render_with(element, RenderOptions)`.
- `TestInstance`:
  - `last_frame(&self) -> &str`
  - `frames(&self) -> &[String]`
  - `rerender(&mut self, element)`
  - `settle(&mut self)`
  - `unmount(self)`; dropping it also unmounts.
- Each present records one frame, `Frame::serialize()`: Static output first, then the live frame, as in Ink's debug write `fullStaticOutput + output`.
- `render` and `rerender` run one `render_if_due` pass. `rerender` replaces the root element and reconciles it against the mounted tree.
- `settle` runs passes until `render_if_due` returns `None`. It stands in for Ink tests' `await delay(..)` and `act()`.
- Test code can write a `State` between calls. The next `settle` renders the change.
- Several instances live on one thread at once (RC5, RC6, RC8-RC11).
