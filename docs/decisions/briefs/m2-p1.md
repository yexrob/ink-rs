## 1. The output layer

Add `src/output.rs`, with submodules as you see fit. Everything in it is `pub(crate)`.

### Input and output

Per frame, the layer takes:
- `&paint::Frame`, with two parts:
  - `live`: the rows of the live region.
  - `static_lines`: in this layer, the new Static rows to write above the live region in this frame. Today paint fills it with every item; phase 2 changes paint so it holds new items alone. Do not change paint.
- The declared cursor position, `Option<(x, y)>`, relative to the top-left of the live frame (Ink's `useCursor`).
- The viewport, `columns × rows`.

It appends bytes to a `Vec<u8>`. When the screen would not change, it appends nothing.

### Methods

- **Constructor:** takes a `synchronized: bool`. Phase 2 decides it from interactive mode and the TTY.
- **`clear`:** erases the live region and leaves the cursor where the region started. The next frame is written as a first frame there (Ink `log.clear()`).
- **`done`:** for exit. It returns the cursor to its rest position. When the frame filled the viewport, it writes `\r\n`. Then it shows the cursor (Ink `log.done()`, plus the design.md rule on `\r\n`).

### Rules

These are the rules from design.md 终端输出. Cite the Ink source where a rule comes from.

1. **State.** The layer keeps the cells of the live region as they are on screen, where the cursor is relative to the region, and whether the cursor is shown.
2. **First frame.** The first frame hides the cursor with `CSI ?25l`. Ink creates its log with `showCursor: false`.
3. **Cell diff, per row.**
   - Write from the first changed cell to the last changed cell. Align both ends to glyph boundaries: a `Cell::Continuation` belongs to the glyph before it.
   - Styles switch at changes. A written segment starts and ends in the default style; `text::styled::serialize` does this for a slice of `StyledChar`.
   - When the new row's content ends before the old row's content, erase the rest with EL (`CSI K`).
   - Never write EL right after writing the last column. In the pending-wrap state, xterm's EL erases the last cell (LS5).
   - What counts as content follows `paint`'s `row_to_line`: trailing unstyled blanks are not content, and styled blanks are.
4. **Moves.**
   - Moves are relative: CUU, CUD, CR, CHA.
   - Rows below the previous frame's last row are reached by writing `\r\n`, which scrolls at the bottom margin. CNL and CUD do not scroll there; see the comment in Ink's `src/log-update.ts` near line 291.
   - Never rely on the terminal turning `\n` into `\r\n`.
5. **Height cap.**
   - The live region is at most `rows` high.
   - A taller frame shows its bottom `rows` rows. The cut rows are not written.
   - No clear-screen, and no full redraw positioned with CUP.
6. **Cursor rest position** (Ink `src/ink.tsx:723-727`):
   - A frame shorter than the viewport leaves the cursor at column 1 of the row below the frame.
   - A frame whose height is at least `rows` leaves the cursor on its last row, with no trailing newline.
   - Handle the transitions as a frame grows into full height or shrinks out of it.
7. **Empty frame.** A frame with no live rows counts as one empty row, as in Ink: `Output.get()` yields `''`, and `'' + '\n'` is written.
8. **Shrink.** Rows that are no longer part of the frame are erased, and the frame stays where it is (Ink's diff path).
9. **Declared cursor.**
   - After the frame, move to `(x, y)` and show the cursor with `CSI ?25h`.
   - The next write starts by hiding the cursor and returning to the rest position.
   - A cursor-only change writes the moves alone.
   - A `y` past the last row clamps to the last row (Ink `cursor-helpers.ts:132`). A `y` inside the cut rows clamps to the first visible row.
10. **Static rows.** When `static_lines` is not empty:
    - Return to the top of the live region and erase down with `CSI J`.
    - Write each static row followed by `\r\n`.
    - Write the live frame below them as a first frame.
    - The static rows scroll into scrollback as the terminal scrolls. Ink does the same in three writes (`src/ink.tsx:802-815`).
11. **Synchronized output.** When `synchronized` is set, wrap each non-empty write in `CSI ?2026h` … `CSI ?2026l` inside the same buffer. An unchanged frame writes nothing, the pair included.

### What to port

1. **Port as screen assertions.**
   - Covered: tests whose intent can be stated as screen rows, scrollback rows, cursor position and visibility, or "writes nothing". These are classes S, S←B and Z in `tests-output.md`.
   - Expected screen: it follows from the test's input frames and Ink's placement rules, namely the rest row, the trailing newline, and the cursor suffix.
   - Ink asserts rows through `reconstructTerminalLines`: take the expected rows from the test and from `expectations/`.
   - Feed whatever the test writes before the frames, such as `shell\r\n`, into the parser first.
2. **LS5.** Port it as a screen assertion, plus a byte assertion that no EL follows the last cell of a full-width row. vt100 cannot detect the pending-wrap erase.
3. **`clear()` and `done()` tests** (LU11-13, LU19-22). Port each one whose intent is the screen after `clear` or `done`.
4. **Duplicates.**
   - When a standard-mode test and an incremental-mode test assert the same scenario, port the first in Ink's order. List the other as a duplicate that differs only in `incrementalRendering`. The pairs are in `tests-output.md` §5.
   - A test that exists only in incremental form is ported under its own name.
5. **Not applicable.** List each with its reason in `docs/ink-tests.md`. These tests pin one of:
   - Ink's write granularity or write count;
   - an Ink-only method: `sync`, `reset`, `willRender`, `getCursorPosition`;
   - the line-update algorithm (LC2-LC6);
   - the reducer itself (LS2).
6. **Phase 2.** LC8 and LB4 go through the public `render` and need the instance (LC8 also needs the alternate screen). Leave them listed under M2.

If a ported test's expected screen differs from what Ink's own screen would be, stop and report it rather than changing the expectation.
