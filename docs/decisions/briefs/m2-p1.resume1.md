Decision on the trailing-newline conflict. Go ahead and implement the brief with these rules.

In Ink's public `render`, a frame is written without a trailing newline exactly when `height >= rows` (src/ink.tsx:723-727). The log-update unit tests pick the trailing newline by hand. Our layer derives it from the viewport, as design.md specifies. So the viewport stands in for the trailing newline:

1. **Pick the viewport per test.** Choose `rows` so that the frame the test asserts on gets the placement Ink gives it:
   - a frame that ends with `\n` is shorter than `rows`;
   - a frame without `\n` has `height == rows`.
   For example: LU40 uses `rows = 1`; LU41 and LU43 use `rows = 2`; LU46 uses `rows = 3`. Earlier frames in the same test then follow our rule. Assert the screen after the frame the test asserts on.
2. **Shrinks out of full height** (LU44): no fixed viewport gives both of Ink's placements.
   - Use the height of the taller frame as `rows`.
   - Keep the test's intent: the dropped row is erased and the remaining row is untouched.
   - The cursor rests on the row below the shorter frame, per design.md. This is also where Ink's public `render` leaves it after leaving fullscreen through its clear path.
   - Record the test in `docs/ink-tests.md` under 与 Ink 测试的差异, with this reason.
   - A shrink with a declared cursor (LU45) needs no deviation, since the declared position decides where the cursor ends.
3. **LU42 is not ported.** Its two frames have the same rows and differ only in the trailing newline. In ink-rs that change happens only when the viewport shrinks onto the frame, which is a resize, and resize is phase 3 (terminal-resize tests). List LU42 under the new `## M2 文件中不移植的测试` section with this reason.
4. **Other tests** in log-update.tsx, log-update-sparse.ts and log-update-columns.tsx that take a no-newline frame (LS3, LS5, LC7, LU47-LU51): apply rules 1 and 2.

The rest of the brief stands. Run only the commands it lists, and report in the format it asks for.
