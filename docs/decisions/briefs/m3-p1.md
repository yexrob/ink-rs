## 1. What to build

A core module `src/input` (`src/input/mod.rs` or `src/input.rs`, your choice; match `src/text`). Pure: no I/O, no clock.

1. **UTF-8 decoding with carry** (Ink calls `stdin.setEncoding('utf8')`, a Node `StringDecoder`). Bytes arrive in reads of any size; a character split across reads is joined; an incomplete tail waits for the next read; invalid bytes become U+FFFD (`<[u8]>::utf8_chunks` gives the maximal-subpart rule). Tested in a later phase through split reads (kitty-keyboard KK-71); no unit test here unless you find a case the later test does not reach.
2. **The tokenizer** (`input-parser.ts`): an `InputParser` with `push`, `has_pending_escape`, `flush_pending_escape` and `reset`, the event type (text or paste), and `is_complete_control_sequence`. Same splitting rules: text runs, the single control bytes it splits out, CSI with the `\e[[` prefix and the rxvt `$` final, SS3, double ESC, ESC + code point, pending incomplete sequences, bracketed paste.
3. **The key decoder** (`parse-keypress.ts`, the string overload only): `parse_keypress(&str) -> ParsedKey`, kitty forms first (`CSI … u` and the special-key form), then the legacy branches, the key-name table and the modifier decoding. Keep the `ParsedKey` fields that Ink's pipeline reads (`App.tsx` readable handler and `handleInput`, `use-input.ts:176-237`) and that the ported tests assert; drop the rest and list them in the report.
4. **The key mapping** (`use-input.ts:176-237`): the public key type and the function that turns a `ParsedKey` into `(input, key)`.
   - Name the type `KeyEvent`: `Key` is already the element key (`src/element.rs`). Fields in snake case, `return` → `enter`, `super` → `super_key`, `eventType` → `event_type: Option<KeyEventType>` with `Press`, `Repeat`, `Release`. Rustdoc on each field, saying when it is set; note that a line feed parses as Ink's `enter` key name and does not set `enter`.
   - The rules of input.md §2.4: kitty text, legacy Ctrl, the sequence, the non-alphanumeric names, the stripped ESC, the forced shift.
   - Its tests are hook-level and come with `use_input` in a later phase. Do not export it at the crate root yet.

Porting notes:
- Ink indexes JavaScript strings by UTF-16 code unit and uses regular expressions. Port the behaviour on Rust strings. Where Ink handles surrogate pairs, the Rust code works on `char`s. Kitty code points that are surrogates or above U+10FFFF still arrive as numbers and keep Ink's empty-key rule.
- No new dependencies: replace each regex with matching code, and quote the regex it replaces in a comment so a reader can compare.
- Comments say why and cite the Ink source (`src/parse-keypress.ts:485-489`).
- The module has no caller outside tests until a later phase. Declare it in `src/lib.rs` with `#[cfg_attr(not(test), expect(dead_code, reason = "…"))]` naming the phase that wires it in, so the attribute must go when the caller arrives. No other `allow`s.
