## 1. What to build

### 1.1 Public API

```rust
// Scope
pub fn use_focus(&mut self, options: FocusOptions) -> bool        // is focused
pub fn use_focus_manager(&mut self) -> FocusManager

// crate root
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct FocusOptions {
    pub active: bool,          // Ink isActive, default true
    pub auto_focus: bool,      // default false
    pub id: Option<String>,    // default: an id generated per hook instance
}
impl Default for FocusOptions { /* active: true, auto_focus: false, id: None */ }

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct FocusManager { /* runtime id; private */ }
impl FocusManager {
    pub fn enable_focus(self);
    pub fn disable_focus(self);
    pub fn focus_next(self);
    pub fn focus_previous(self);
    pub fn focus(self, id: &str);
    pub fn active_id(self) -> Option<String>;
}
```

- `FocusManager` is a UI-thread `Copy` handle that resolves its `Store` by runtime id, like `OutputWriter`. Handlers and effects capture it without cloning. After the app unmounts, mutators do nothing and `active_id` returns `None`.
- `active_id` reads the live state. Ink exposes `activeId` as the value of the last render; the live read gives the same value after a step and lets handlers read focus.
- The mutators call `assert_not_rendering()`, as `State::set` does. They apply at once, in call order: each call sees the result of the previous one (FS1 steps 1–3).
- Ink's `useFocus` also returns `focus(id)`. It is the manager's method; `use_focus_manager().focus(id)` covers it, so `use_focus` returns only the flag.
- Rustdoc on every public item: what it does, the default, and the Ink behaviours a user can observe (registration order, duplicate ids, Tab and Esc rules, disable clears focus, enable does not restore it).

### 1.2 Focus state (Store)

One per runtime, in `Store`:

- `entries`: `{ key, id: String, active: bool }` in registration order. `key` identifies the hook instance; a duplicate id is allowed.
- `active: Option<String>`. `Some("")` is a valid id (FE1–FE3).
- `enabled: bool`, true at start. A change is visible to later calls at once (FS1 step 6).
- The readers to re-render on an `active` change (below).

Rules (Ink `App.tsx` 537–703, research §11):

- Register appends `{key, id, active: true}`. When `auto_focus && enabled`, `active = active.or(id)`.
- Unregister removes this hook's entry only, and clears `active` when it equals the id. Ink removes every entry with the id; no test tells them apart, and removing one keeps a remaining duplicate registered. Activate and deactivate also act on this hook's entry; deactivate clears `active` when it equals the id.
- Navigation walks the first entry per id (Ink `uniqueFocusables`). `focus_next`: the next active entry after the current id, else the first active entry. `focus_previous`: the previous active entry before the current id, else the last active entry; from no focus this is the last active entry, as in Ink's code (its readme says first).
- `focus(id)`: sets `active` when any entry with that id is active (all entries, not the unique list, as in Ink). It does not check `enabled`, as in Ink.
- `enable_focus` sets the flag only. `disable_focus` clears the flag and `active`.
- Generated ids: unique per hook instance within the runtime, stable across renders (a `use_memo`). The format is untested; pick one a user is unlikely to type, and say so in the rustdoc of `FocusOptions::id`.

Re-render: in Ink every `useFocus` and `useFocusManager` consumer reads `activeId` from context, so each re-renders when it changes. Keep a list of the reader instances' `Weak<Dirty>`; `use_focus` and `use_focus_manager` add their instance on the first render. When `active` changes value, mark each live, mounted reader and call `store.queue.notify()`, as `State::set` does; drop dead entries. A change inside a layout effect must re-render the readers in the same commit, as a state write there does, so an autoFocus app paints `First ✔` in its first frame.

### 1.3 `use_focus` effects

Per hook instance, in this order, each a layout effect (design decision: focus shows in the first frame; Ink uses passive effects, and the tests read settled frames either way):

1. Register, dependencies `(id, auto_focus)`; the cleanup unregisters. A changed id or auto_focus re-registers at the end of the list (F37).
2. Activate or deactivate, dependencies `(active, id, auto_focus)`, so it runs after every re-registration (Ink `use-focus.ts`). An inactive autoFocus hook therefore registers, takes focus, and gives it up at once, and the first active autoFocus registrant wins (F36).

Then the raw-mode hold, a passive effect with dependency `active`, like `use_input`: while active, the hook holds a registration in the shared holder list, so Tab and Esc reach the runtime with no `use_input`. Add a `Focus` holder kind next to `Input` and `Paste` (no handler; identity by an `Rc` token or the entry key).

Return `active == Some(id)` from the render-time state.

### 1.4 Keys (Runtime::emit_input)

After the Ctrl+C rule and before the `use_input` handlers, apply on the parsed key:

- Esc: when `enabled`, name `escape`, not a release, and none of shift, ctrl, meta, super, hyper → `active = None` (F9–F16). A lone `\x1b` reaches this after the 20 ms flush (F20, F43).
- Tab: when `enabled`, entries non-empty, name `tab`, not a release, and none of ctrl, meta, super, hyper → shift calls `focus_previous`, otherwise `focus_next`. A repeat counts as a press (F1–F8).
- Both keys still reach the `use_input` handlers; focus does not consume them.

Ink registers its Tab listener in an App effect, so handlers registered at mount see Tab before focus moves. Ink's `activeId` is render state, so its handlers cannot observe that order. Here Tab is applied before every handler, and a live `active_id` read in a handler sees the new focus. Say this in a comment and in the report.

### 1.5 Raw mode (App)

`use_focus` holds raw mode only when stdin is a TTY (Ink checks `isRawModeSupported` and skips; `use_input` and `use_paste` throw). At the end of the step:

- stdin is a TTY: raw mode is on when any holder exists, as now.
- stdin is not a TTY: an `Input` or `Paste` holder still ends the app with the `ErrorKind::Unsupported` error; `Focus` holders alone leave raw mode off and do not error.

Add the `Runtime` accessor App needs (for example `focus_holders()`), next to `paste_holders()`.

### 1.6 Test driver (`testing::render`)

The Ink focus tests use debug frames, which belong to `TestInstance`. Add:

- `TestInstance::input(&mut self, bytes: impl AsRef<[u8]>)`: one stdin read at the instance clock through `Runtime::input`, then `settle`. Input reaches the runtime whenever a holder exists; there is no App, so no raw-mode check and no exit.
- `TestInstance::advance(&mut self, duration: Duration)`: moves the instance clock, runs `Runtime::flush_input`, then `settle`. It hands a lone Esc over after 20 ms.
- A fake clock on `TestInstance`, started at mount; `step` uses it in place of `Instant::now()`.

Rustdoc both, in the style of `TestApp::input` and `TestApp::advance`. Update the crate doc in `src/lib.rs` that lists what `testing::render` offers, if it needs it.
