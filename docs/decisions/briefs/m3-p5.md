### 1.2 Window size

`ProcessTerminal::size` uses rustix `tcgetwinsize` on stdout, as design.md says. On failure it returns `None`; `WindowSize::resolve` already falls back per dimension.

### 1.3 Raw mode and the reader (process-wide)

Put this in a new module under `src/driver/` (for example `src/driver/stdin.rs`). One state per process, behind a mutex:

- **Holders**: the live apps that hold raw mode, in the order they turned it on. Input goes to the most recent holder (design.md 多个应用). When it releases, the next most recent receives input.
- **termios**: the first acquire reads stdin's termios with `tcgetattr`, keeps it, and applies libuv's raw mode: clear `BRKINT ICRNL INPCK ISTRIP IXON` and `ECHO ICANON IEXTEN ISIG`; set `CS8`; keep `OPOST` and `ONLCR`; `VMIN=1`, `VTIME=0`. Use the `tcsetattr` optional actions libuv uses (`uv_tty_set_mode`, `uv_tty_reset_mode`); cite them. The last release writes the saved termios back.
- **Reader thread**: started by the first acquire, stopped by the last release. It owns a dup of stdin and waits with `filedescriptor::poll` on stdin and the read end of a `socketpair`, with no timeout. Each readiness makes one `read` into a buffer, and the bytes go to the current target as `Message::Input(Vec<u8>)`. Stopping writes one byte to the wake end and joins the thread. The fd stays blocking; never set `O_NONBLOCK` (design.md 读线程 says why).
  - EOF (`read` returns 0): the thread ends, and the target app gets `Message::InputEnded`. The app keeps running; input no longer keeps it alive (1.5). A later acquire starts a new reader.
  - A `poll` or `read` error other than `EINTR` ends the thread and is recorded as the target app's I/O error, the first one wins, as writes do; the loop then ends with `Err(Error::Io)`. This includes the `FD_SETSIZE` error `filedescriptor::poll` returns on macOS for a high fd.
- No user code runs under these locks. The panic hook can run on a thread that holds an app's `RestoreState`; keep the lock order fixed and say what it is in a comment.

`ProcessTerminal::set_raw_mode(true)` acquires for this app; `false` releases. A failure is retained for `take_error`, as the trait says. The terminal needs its app's message sender for input; restructure `ProcessTerminal::new` / `register` as you see fit.

### 1.4 Restore

Raw mode must end on every path that restores the terminal:

- normal unmount (`App::unmount` already turns raw mode off first);
- `Registration::drop` (mount or cleanup panicked before App finished);
- the panic hook (apps owned by the panicking thread; all apps under `panic = "abort"`);
- the signal thread's terminate path and the loop's `Stop::Signal` path.

Release this app's hold on each path, so the last release restores termios and stops the reader. A second release is a no-op.

### 1.5 Driver loop and liveness

- `Message::Input(bytes)`: concatenate adjacent `Input` messages taken in one drain and call `App::input(&bytes, Instant::now())` once, as Ink loops `stdin.read()` until empty. Keep the order relative to other messages.
- `Message::InputEnded`: the app's stdin has ended.
- `natural_end` gains: the app does not hold raw mode, or its stdin has ended. This is Node's `stdin.ref()`: an active `use_input` keeps the process alive (E13). Add the `App` accessor you need.

### 1.6 External output newlines

Remove the M2 rewrite in `AppOutput::external_write` that turns a `\n` not preceded by `\r` into `\r\n`; termios keeps `OPOST` and `ONLCR` now, as Node's raw mode does. Keep appending `\r\n` when the data does not end in `\n` (design.md 外部输出的换行). Update the comment.

Tests feed `TestTerminal` output to vt100, which has no line discipline. Model `ONLCR` in `tests/common::Screen` for TTY output: every `\n` written to the terminal reaches vt100 as `\r\n`, as a PTY with `ONLCR` delivers it. Then check every test whose expectations change. A byte-level assertion on external-write data changes to the bytes ink-rs now writes; a screen assertion must keep its expected screen. Report each test you changed and why.
