## 1. Public API

```rust
impl AppHandle {
    pub fn suspend_terminal(&self, f: impl FnOnce() + Send + 'static) -> Result<(), AlreadySuspended>;
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct AlreadySuspended;   // Display: "the terminal is already suspended"; impl std::error::Error

pub struct Options { /* existing fields */ pub suspend_on_ctrl_z: bool }   // default true

pub trait Terminal { /* existing */ fn stop_process(&mut self) {} }       // crate-private trait

impl TestApp {
    pub fn suspend_terminal(&mut self) -> Result<(), AlreadySuspended>;
    pub fn resume_terminal(&mut self);
}
impl TestTerminal {
    pub fn stop_process_calls(&self) -> usize;   // shared by clones, like raw_mode_calls
}
```

- Export `AlreadySuspended` from `lib.rs` next to `AppHandle`.
- `suspend_terminal(f)`:
  - The app has closed (unmount began): drop `f` without calling it and return `Ok(())`, as `update` does. Differs from the research, which runs `f`.
  - A request is queued or a suspension is active: return `Err(AlreadySuspended)`.
  - Otherwise queue `f` in a one-slot request and wake the driver.
  - Drop a rejected `f` after releasing the queue lock, as `request_exit` does.
- The rustdoc of `suspend_terminal` says:
  - at the end of the next step the app hands the terminal over: frame erased, cursor shown, raw mode, bracketed paste and kitty flags off, alternate screen left;
  - `f` runs while the app's loop waits; the sync driver runs it on the thread that called `wait_until_exit`;
  - after `f` returns, the app takes the terminal back and redraws;
  - non-interactive apps hand over input only and keep writing output;
  - `f` should block until the child process exits; report results through `update` or `exit_with*`; a panic in `f` unwinds like a handler panic.
- `Options::suspend_on_ctrl_z` rustdoc: a Ctrl+Z press or repeat stops the process group as the terminal's suspend key does; the shell's `fg` resumes the app; those events do not reach `use_input`, a release does. Mirror the `exit_on_ctrl_c` doc.
- `TestApp::suspend_terminal()` and `resume_terminal()` are the handle form for tests that act during a suspension (rerender, input, resize, unmount). `suspend_terminal()` follows the same Err rule as the handle. `resume_terminal()` resumes and runs a step.

## 2. Core: `App`

### 2.1 State

- Two suspension reasons: `Api` (a `suspend_terminal` request or the test handle form) and `Stop` (job control). The app is suspended while either is set. Keep them as two bools or a tiny struct in `App`; a `Reason` enum is the argument type.
- `UpdateQueue` gains the request slot and an "active" flag. Taking the request and setting the flag happen under one lock, so a request from another thread cannot slip in between. Resume of `Api` clears the flag. `is_idle` counts a queued request. `close` drops a queued request.
- `AppOutput` gains `suspended: bool`. Replace `kitty_protocol: bool` with the pushed flags, and keep the flags popped at suspension for resume.

### 2.2 `App::begin_suspension() -> Option<Box<dyn FnOnce() + Send>>`

Drivers call it after `render_if_due`. It returns `None` when the app is unmounted, an exit is pending, or no request is queued. Otherwise it takes the request, calls `suspend(Reason::Api)`, and returns `f`.

### 2.3 `App::suspend(reason)`

1. Set the reason. If the app was suspended already or is unmounted, stop here.
2. `kitty_query = None` (cancels a pending `KittyKeyboard::Auto` query; no flags get pushed later).
3. Reset the input parser and its 20 ms Esc deadline (Ink `pauseInput`). Add a small `Runtime` method for this.
4. One write: `restore_modes()` (`?2004l` when paste is on, `<u` when kitty flags are pushed), then, when interactive, the screen part:
   - alternate screen: `?1049l?25h`;
   - inline: `Output::clear` followed by `Output::done`, synchronized when stdout is a TTY.
   The restore snapshot of that write is empty. Set `paste_mode = false`, move the pushed kitty flags to the resume slot, set `suspended = true`.
5. `set_raw_mode(false)` when raw mode is on; `self.raw_mode = false`.

Input handover (steps 2, 3, 5 and the mode bytes) happens in every mode. The screen part happens only when interactive. Ink skips everything when not interactive; we hand input over anyway so a child process gets stdin. No Ink test observes the difference.

No throttle flush: a pending throttled frame stays pending and the resume paint shows it.

### 2.4 While suspended

- Commits, layout effects and passive effects run.
- Interactive: paint and `after_write` are skipped; `pending` stays set. `<Static>` items committed now stay in the runtime and reach the resume paint (Ink drops them; keep ours).
- The wake in `render_if_due` must not return `Some(now)` for a pending interactive paint while suspended, or the sync loop spins. Animation and input deadlines keep their own wakes.
- `App::input` drops the bytes.
- `App::resize` updates `AppOutput` columns and rows and `Runtime::resize`, and does not set `resize_from`.
- `App::clear` does nothing.
- Interactive: external writes (`use_stdout`, `use_stderr` writers) are dropped. Non-interactive: they pass through, as in Ink.
- `restore_bytes()` returns empty while suspended and interactive.
- The raw-mode and paste-mode sync at the end of `render_if_due` is skipped. The non-TTY `Unsupported` check stays.
- Unmount: no raw-mode call (raw is off). Interactive: no paint, and `AppOutput::restore` passes an empty buffer to `Terminal::restore`, which still marks the terminal restored. Non-interactive: the final frame is written as usual.

### 2.5 `App::resume(reason)`

1. Unmounted, or an exit is pending: return and keep every flag set, so unmount writes nothing.
2. Clear the reason (for `Api`, also clear the queue's active flag). Resume of a reason that is not set is a no-op: a `Continue` after an external `SIGSTOP` redraws nothing.
3. Still suspended by the other reason: return.
4. Interactive:
   - re-query `terminal.size()` and update dimensions as in 2.4 (no `resize_from`);
   - one write: `?1049h\x1b[H` on the alternate screen, then `CSI >{flags}u` when flags were popped; its snapshot is `restore_bytes()` after `suspended` is cleared;
   - fresh `Output`, `last_frame = None`, `last_cursor = None`, `resize_from = None`;
   - `pending = true`, `deadline = None`, so the next step paints at once. On the alternate screen that paint prepends the Static history as it already does.
5. Non-interactive: push the popped kitty flags, if any.
6. Raw mode and bracketed paste come back through the normal sync at the end of the next step, after the paint.

### 2.6 Ctrl+Z

- `Runtime` gains `suspend_on_ctrl_z` (set from `Options` in `App::new`, like `exit_on_ctrl_c`) and a stop-request flag.
- In `emit_input`, after the Ctrl+C rule: `suspend_on_ctrl_z && name == "z" && ctrl && !shift && !meta && !super_key && !hyper && event_type != Release` sets the flag and returns, consuming the event. The paste channel never triggers it.
- `App` takes the flag after `Runtime::input` (in `App::input`) and after `flush_input` (in `render_if_due`), and calls `Terminal::stop_process()`.
- `ProcessTerminal::stop_process`: `rustix::process::kill_current_process_group(Signal::TSTP)`, ignoring the error. The whole group stops, as the tty driver does for `cargo run` or a wrapper script. Add the rustix feature `process`.
- `TestTerminal::stop_process` counts calls.

## 3. Sync driver

### 3.1 Messages

Add `Message::Stop(mpsc::Sender<()>)` and `Message::Continue`. In `run_loop`:
- `Stop(ack)`: `app.suspend(Reason::Stop)`, then drop `ack`. The teardown bytes are written and stdin is released before the ack drops.
- `Continue`: `app.resume(Reason::Stop)`.
- `natural_end` must return false while the app is suspended. Releasing raw mode ends input, and without this guard a Ctrl+Z would end an app that has no handles.

### 3.2 Running `f`

`run_loop` takes `&mut Registration`. After `render_if_due` and the error and exit checks:

```text
if let Some(f) = app.begin_suspension() {
    registration.leave_loop();            // in_loop = false under the registry lock
    drain receiver: Stop(ack) -> app.suspend(Stop), drop ack; keep every other message, in order
    f();
    registration.rejoin_loop();           // in_loop = true under the registry lock
    app.resume(Reason::Api);
    process the kept messages before new ones, then step again at once
}
```

- The registry lock makes the in_loop switch atomic with the signal thread's Stop fan-out: a Stop sent before `leave_loop` is in the channel and gets drained; after it, the signal thread skips this entry. The drain must happen before `f`, or the signal thread waits on an ack until `f` returns.
- `leave_loop` and `rejoin_loop` only toggle this entry's flag. Do not reuse `enter_loop`; it handles nested waits and would lose the suspended outer loop.
- A SIGINT, SIGTERM or SIGHUP during `f` finds the entry outside its loop and takes the existing emergency path (restore, terminate). That is Ink's outcome.
- Do not catch a panic in `f`.

### 3.3 After the loop

In `wait_until_exit`, right after `run_loop` returns: `leave_loop()` and drop every queued message. A Stop sent between the loop's end and the registration's drop must not keep its ack alive; the `Stop::Signal` branch parks forever with the receiver alive.

## 4. Signal thread (`process.rs`)

- Add SIGTSTP and SIGCONT to the `Signals` iterator. Do not add a conditional default for SIGTSTP: the signal thread handles it in every state.
- SIGTSTP:
  1. Orphan guard: `rustix::process::getsid(None)` equals `getpgrp()` → ignore the signal. A session leader's group (`setsid`, the portable-pty harness) has no shell that would continue it; the kernel discards a default SIGTSTP for orphaned groups, but `emulate_default_handler` raises SIGSTOP, which nobody would undo. Comment that a full orphan check needs other processes' parents.
  2. Create `(ack, done) = mpsc::channel::<()>()`. Under the registry lock, send `Message::Stop(ack.clone())` to every entry whose `in_loop` is set. Release the lock, drop `ack`, then block on `done.recv()` until it returns `Err` (every loop dropped its sender, or its receiver is gone).
  3. `signal_hook::low_level::emulate_default_handler(SIGTSTP)`; it raises SIGSTOP and returns after SIGCONT.
  - Entries outside their loop are skipped: an owner blocked in `f` already handed over; an app between `render` and `wait_until_exit` stops without teardown (document this in a comment).
  - With no entries, step 3 runs at once.
- SIGCONT: send `Message::Continue` to every entry, in or out of its loop.
- Keep the lock-order comment at the top of `process.rs` true.

## 5. Testing driver

- `TestApp::step` loops: run the step; if `begin_suspension()` returns `f`, call `f()`, then `resume(Reason::Api)`, and repeat. Return the last step's wake time.
- `TestApp::suspend_terminal()`: the queue's Err rule, then `suspend(Reason::Api)` and mark the queue active. `resume_terminal()`: `resume(Reason::Api)`, then `step()`.
- `f` is `Send` and `TestTerminal` is `Rc`: tests record from `f` into `Arc<AtomicBool>` or `Arc<Mutex<..>>`. Ordering against raw-mode calls is structural: one step runs the teardown, `f`, then the resume.
