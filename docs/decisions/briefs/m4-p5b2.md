### suspend-terminal

State: `counter` (number), `status` (string, starts `ready`). `use_input`:
- `q` → `exit()`;
- `+` → counter + 1 (use `State::update`, so several keys in one chunk all count);
- `e` / `r` → set status `suspended — child owns the terminal`, then `suspend_terminal(f)`. `f` runs the child with inherited stdio and waits for it:
  - `e`: `sh -c "$EDITOR"`, `EDITOR` defaulting to `vi`;
  - `r`: `sh -c` with the same `printf ...; read -r line; printf ...` script as Ink (copy it exactly).
  
  Then `f` reports the result back to the UI thread through `AppHandle::update`: status `resumed — Ink redrew and the counter is preserved` on success, `child failed: {message}` otherwise. Messages as Ink's `runChild`: `Child process exited with code {code}`, `Child process terminated by signal {name}` (`signal_hook::low_level::signal_name`, falling back to the number), or the spawn error's `Display`. If `State` is not `Send`, pass the result through another `Send` path and report which.
  
  `suspend_terminal` returns `Err(AlreadySuspended)` when a handover is queued; ignore it as Ink's `void` does (the key is dropped).

The frame: a round-bordered column with `padding_x(1)`: bold `suspendTerminal() demo`, `Counter: ` with the number in green, the status dim, then `margin_top(1)` and the four key lines.
