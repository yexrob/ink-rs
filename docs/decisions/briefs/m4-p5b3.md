## 1. jest

`examples/jest/{main.rs, app.rs}`. `app.rs` holds `pub fn app() -> Element`, the `Jest` component, and `summary` / `test` as plain functions returning `Element` (Ink's `Summary` and `Test`). Keep Ink's texts, colors, widths and margins.

- State: start time (`Instant` at mount), completed results, running results. A result is a path and a status (`runs`, `pass`, `fail`).
- One `use_future((), ..)` runs the 10 paths with concurrency 4, as Ink's `PQueue`. Run four worker futures with `tokio::join!` inside the task, pulling paths from a shared index, so aborting the `use_future` task cancels all of them. Each run: push `runs`, sleep a random delay below 1 s, remove it from running, push `pass` or `fail` with probability 1/2. Use `State::update` for every list change.
- Randomness: a local xorshift seeded from `std::collections::hash_map::RandomState` (no `rand`).
- `Static` for completed results, keyed by path.
- `Time:` uses Ink's `ms` short format: `{n}ms` below 1 s, then rounded `{n}s`, `{n}m`, `{n}h`, `{n}d`. A small fn in `app.rs`.
- When the task ends, the app has no handles and no input, so `wait_until_exit` reaches its natural end, as the Node process exits.

## 2. subprocess-output

`examples/subprocess-output/{main.rs, app.rs}`. Ink stubs `spawn` in its tests. Here the component depends on an interface, not on a process:

```rust
pub enum Chunk {
    Bytes(Vec<u8>),
    /// The command could not start; Ink shows `error.message`.
    Failed(String),
}

/// Renders the last lines of a byte stream.
pub fn app(source: tokio::sync::mpsc::UnboundedReceiver<Chunk>) -> Element;
```

`app` wraps the receiver in a props type that compares by pointer identity (for example `Rc<RefCell<Option<_>>>` with `Rc::ptr_eq`); a `use_future((), ..)` takes it out and loops on `recv().await`.

- Text state follows Ink: `Bytes` appends the decoded text, then keeps the last 5 `\n`-separated lines (`split('\n')`, last 5, joined with `\n`). `Failed(message)` replaces the text with the message.
- UTF-8 decoding across chunks, as Node's `setEncoding('utf8')`: keep an incomplete trailing sequence until the next chunk (`<[u8]>::utf8_chunks`); invalid bytes become U+FFFD. Put the pending bytes and the text in one small struct with a `push(&mut self, bytes: &[u8])` so the component holds one `State` of it.
- ANSI stripping at render, as Ink's `stripAnsi(output)`: a local fn that removes CSI (`ESC [` … final byte 0x40–0x7E, and C1 `0x9B`), OSC (`ESC ]` … BEL or `ESC \`), and other two-byte `ESC` sequences. A sequence split across chunks is stripped once complete, since the text keeps it whole.
- Layout: column with padding 1: `Command output:`, then `margin_top(1)` and the stripped text.

`main.rs` is the production feeder: it spawns `cargo run --quiet --example jest` (Ink spawns `npm run example examples/jest`) with stdout piped and stderr discarded, and forwards stdout reads to the channel from a reader thread (`UnboundedSender::send` is synchronous). A spawn error sends `Failed(error.to_string())`. tokio's `process` feature is not enabled in this crate; do not add it. The tests are the local feeder.
